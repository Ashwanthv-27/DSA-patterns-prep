# DSA Patterns & Interview Preparation

A collection of Data Structures and Algorithms problems solved as part of my preparation for technical interviews.

The focus of this repository is not just solving problems, but understanding how to approach them, recognize patterns, compare different solutions, and improve from a straightforward approach to an efficient one.

## How I Approach Problems

For each problem, I try to work through the following process:

1. Understand the problem and constraints
2. Come up with a straightforward solution
3. Analyze its time and space complexity
4. Identify the bottleneck
5. Look for a suitable data structure, pattern, or algorithm
6. Develop an optimized solution
7. Compare the different approaches
8. Consider edge cases and common mistakes
9. Document the reasoning and lessons learned

### How the categories are used

**Data Structures**

Describe the structures used to store and organize data.

Examples:

* Arrays
* Strings
* Hash Tables
* Linked Lists
* Stacks
* Queues
* Trees
* Heaps
* Graphs

**Patterns / Techniques**

Describe reusable ways of approaching problems.

Examples:

* Two Pointers
* Sliding Window
* Prefix Sum
* Fast & Slow Pointers
* Monotonic Stack
* Complement Lookup

**Algorithms**

Describe specific algorithms or algorithmic approaches.

Examples:

* Binary Search
* BFS
* DFS
* Backtracking
* Greedy
* Divide and Conquer
* Dynamic Programming

**Problems**

Contain the actual problems and solutions. Each problem is categorized by the primary data structure involved, while its solution can reference the patterns, techniques, and algorithms used.

For example:

```text id="z1r3b9"
Two Sum

Problem Category: Array
Data Structure: Array
Supporting Data Structure: Hash Map
Technique: Complement Lookup
Algorithm: Single-pass Hash Map Lookup
```

## Pattern Documentation

Pattern pages focus on understanding the general technique rather than a single problem.

They cover:

* What the pattern is
* When to recognize it
* How it works
* General implementation approach
* Complexity
* Common variations
* Common mistakes
* Problems where the pattern can be applied

## Goal

The goal of this repository is to build strong problem-solving skills for technical interviews by focusing on understanding and pattern recognition rather than memorizing solutions.

The repository will continue to grow as I work through different data structures, patterns, algorithms, and interview problems.
